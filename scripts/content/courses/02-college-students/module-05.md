### Module 2 · The Data Workflow (With AI as Analyst-Buddy)

Great data work follows a repeatable pipeline: **Describe, Clean, Analyse, Visualise, Explain**. Each step has a clear prompt and a clear job, and together they turn a messy dataset into a defensible insight. AI rides along at every step as the analyst-buddy.

The final step matters most: document each stage so your analysis becomes reproducible. Markers and managers reward a documented pipeline because it turns analysis into evidence you can defend.

## Learning Objectives

- Name the five steps of the data workflow
- Write a targeted prompt for each step
- Explain why documentation makes analysis evidence
- Keep AI as analyst-buddy through the whole pipeline

## The Five-Step Pipeline

1. **Describe:** give AI the columns and sample rows; ask it to describe structure and quality issues
2. **Clean:** ask for a checklist of missing-data and outlier decisions before touching anything
3. **Analyse:** ask targeted questions, never open-ended 'analyse this'
4. **Visualise:** ask which chart fits which question, then let AI generate it
5. **Explain:** ask it to write the interpretation, then check every claim
### The ordering rule
- Understand and clean data before any analysis or chart

## Targeted Questions Win

```text
Targeted versus open-ended:
Weak: 'Analyse this dataset for me'
Strong: 'What is the trend in column X over time?'
Strong: 'Compare group A and group B on metric Y'
```
- Specific questions yield specific, checkable answers
- Each answer is easier to verify against your data
- Vague prompts return vague interpretations

## Document to Become Reproducible

### Why documentation is the payoff
- A documented pipeline is a repeatable analysis
- Reproducibility is what markers and managers reward
### The documentation habit
- Log prompts, decisions, and results at each step
- Your analysis becomes evidence, not just output
- Reproducible work survives scrutiny and saves rework

## Key Takeaways

- The pipeline is Describe, Clean, Analyse, Visualise, Explain
- Understand and clean before you analyse or chart
- Targeted questions give specific, checkable answers
- AI stays the analyst-buddy at every step
- Document each stage - reproducible analysis is evidence

### Module 3 · The Code Buddy Method (No Prior Coding Needed)

You do not need to be a programmer to analyse data with AI. The Code Buddy Method is a loop: ask AI to write a small analysis script, run it step by step in a free environment, and when it errors paste the error back and let the AI fix it. This 'copy, run, fix' loop is how thousands of students now analyse real data.

You are still the analyst - you decide the questions and check the answers - but the syntax is someone else's problem. Each loop builds genuine intuition without the pain of learning syntax from scratch.

## Learning Objectives

- Ask AI to write a small analysis script in Python
- Run code step by step in a free environment
- Feed errors back to AI and iterate
- Keep analyst judgment: questions and verification stay yours

## The Loop in Action

- Ask a chat tool to write a small analysis script in **Python (pandas)** for a specific task
- **Run the code step by step** - Google Colab runs in a browser
- When it errors, paste the error back: 'Here is the error, fix it and explain what was wrong'
### Why pandas and Colab
- pandas is the standard library for tables and analysis
- Colab runs it in the browser with no installation

## Loop Until It Works

```text
The copy-run-fix loop:
1. Copy the AI's script
2. Run it in Colab
3. Paste the error back with context
4. Apply the fix and rerun
5. Loop until the output is correct
```
- Each full error message produces precise fixes
- Fixing teaches you more than perfect code ever would

## You Stay the Analyst

### The ownership split
- You decide the questions and check the answers
- AI owns the syntax; you own the meaning
### Why this builds intuition
- Running and fixing builds pattern recognition without memorising
- After ten loops you will read code you feared a month ago
- The analyst-buddy relationship stays intact throughout

## Key Takeaways

- The Code Buddy Method is copy, run, and fix with AI
- Python (pandas) plus Colab is the zero-setup analysis stack
- Paste full error messages back for precise fixes
- You own the questions and the verification
- The loop builds genuine coding intuition without syntax pain

### Module 4 · Choosing the Right Chart

The chart must fit the **question**, not your mood. Choosing the right visual is a skill and AI is genuinely good at it - if you prompt with your question type. The rule is simple: match the chart family to the relationship you are trying to show.

Ask AI to justify its choice, then generate it and label the axes properly. A well-labelled simple chart beats a confusing fancy one every time, because the reader must understand it in seconds.

## Learning Objectives

- Match chart families to question types
- Ask AI which chart tells the story best and why
- Label axes well enough that the chart stands alone
- Prefer simple, honest charts over fancy ones

## The Chart Family Map

- **Comparison (A vs B):** bar chart
- **Trend over time:** line chart
- **Parts of a whole:** pie or stacked bar, used sparingly
- **Distribution:** histogram or box plot
- **Relationship between two variables:** scatter plot
### The matching rule
- Name the question type first, then pick the family
- Mismatched charts mislead no matter how pretty

## Prompt the Choice

```text
The chart-choice prompt:
Given my data and question, which one chart
tells the story best, and why?
```
- Ask for a justification, not just a name
- Generate the chosen chart with AI
- Verify the choice fits your question, not its beauty

## Label Like It Matters

### Axes make the chart honest
- An unlabelled chart is interpretation, not evidence
- Labels are what make a visualisation trustworthy
### Simplicity wins
- One clear message per chart
- A well-labelled simple chart beats a confusing fancy one
- If you must explain the chart, the chart failed

## Key Takeaways

- Match the chart family to the question type
- Line shows trends; bars compare; scatter shows relationships
- Ask AI which chart tells the story best and why
- Labels are what make a chart evidence, not decoration
- A well-labelled simple chart beats a fancy confusing one

### Module 5 · Interpreting Results Honestly

The most common data mistake is not technical - it is **over-claiming**. When you interpret results you must stay inside what the data actually supports. The classic traps are correlation versus causation, small samples, and comparing things that are not like for like.

The anti-trap move is adversarial review: once you have an interpretation, ask AI to attack it and find alternative explanations. Honest limitations are the mark of a mature analyst, and they make your work more credible, not less.

## Learning Objectives

- Explain why correlation is not causation
- Describe the danger of small samples
- Compare only what is like for like
- Use adversarial review to pressure-test conclusions

## The Over-Claim Traps

- **Correlation is not causation:** 'sales rose with ad spend' is not 'ads caused sales'
- **Small samples lie:** an n of 5 is a pattern you cannot defend
- **Compare like for like:** never compare totals from different groups without saying so
### Why they happen
- We narrate patterns; reality needs evidence for the story

## The Adversarial Pass

```text
The devil's-advocate prompt:
Attack my interpretation. What could
alternatively explain this pattern?
```
- Ask AI to attack your reading, never to agree
- Alternative explanations sharpen your claim
- Each attack you survive makes the insight stronger

## Honest Limitation as Strength

### What maturity looks like
- Present what the data supports and say what it does not
- State limitations before someone else does
### Why honesty pays
- Credible analysts are trusted analysts
- Over-claims collapse under one question; honest limits survive
- Adversarial review catches over-claims early

## Key Takeaways

- Most mistakes are over-claims, not technical errors
- Correlation is not causation - and small samples lie
- Compare only like-for-like groups
- Use AI as the devil's advocate on your interpretation
- Honest limitations are the mark of a mature analyst

## Practice Challenge

2. Run the adversarial pass and record the alternative explanations
3. Rewrite your conclusion to state precisely what it does not claim

**Example Quiz**

### Module 6 · The AI-Data Trap List

When you trust AI with numbers, watch for a specific list of traps. AI can invent statistics, analyse columns that do not exist, garnish your conclusion with facts not in the data, and project overconfidence in a neat chart. Each trap is a failure to ground the AI in your actual dataset.

The rule of thumb saves you: **any number you cannot trace to your own data - kill it.** Run this checklist before submitting any data assignment.

## Learning Objectives

- Name the four classic AI-data traps
- Demand that numbers come from your dataset
- Verify column names before trusting analysis
- Apply the kill rule to untraceable numbers

## The Four Traps

- **Made-up stats:** AI can invent means, percentages, and even chart data - demand numbers come from your dataset
- **Wrong columns:** AI may analyse a column that does not exist - check names first
- **Selective stories:** AI will garnish your conclusion with facts not in the data
- **Overconfidence:** a neat chart does not make the analysis sound - your validation does
### The through-line
- Every trap is the AI leaving your data and guessing

## The Kill Rule

```text
The kill rule in practice:
1. Find each number in your report
2. Trace it to your dataset
3. If you cannot, remove it
4. If it is decorated, strip the garnish
```
- Untraceable numbers are fiction - remove them
- Demand that numbers come from your actual dataset
- Flair never justifies a fabricated figure

## The Submission Checklist

### Before you submit
- Every number traces to your data
- Every column name you used exists in the file
- Every claim's story is in the data, not borrowed
### Why the checklist matters
- It converts a gut feeling of trust into verifiable steps
- Run it before every data assignment
- Your validation, not the chart, is what makes it sound

## Key Takeaways

- The four traps: made-up stats, wrong columns, selective stories, overconfidence
- Demand numbers come from your dataset, not the model's memory
- Verify column names before trusting any analysis
- The kill rule: any number you cannot trace, remove it
- Run the checklist before submitting any data assignment
