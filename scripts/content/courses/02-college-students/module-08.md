# Mission 8: Building an AI Mini-Project

## Learning Objectives
- Go from idea to shipped mini-project in one week
- Write a mini project brief and scope it realistically
- Build a small real product with the AI skills from Missions 1–7
- Test your project with real users and iterate
- Package and share it as a portfolio-worthy artefact

---

## The One-Week Project Method

This mission is a 5-day build. Not a vague "someday" project — a scoped, shipped one. Rushing to code kills student projects; a tight brief saves them.

## Day 1: Pick & Scope

**Pick** something small, relevant to your field or interest, and *demonstrable*:

- 📚 Subject + AI: a "study buddy" that turns your notes into practice questions.
- 📊 Data + AI: a script that reads a dataset and emails a one-page report.
- 🌐 Domain + AI: a Q&A bot about your campus, a lab, or a research topic.
- 🛠️ Automation: the Mission 7 workflow elevated into a real tool.

**Scope ruthlessly** (MVP mindset). One user, one problem, one core action:

> "My project is ______. It helps ______ do ______ in under 10 minutes." If you can't finish that sentence, you're not scoped yet.

Deliverables: a 1-page brief (goal, user, core features, tech, risks) + a checklist of 3–4 must-haves (and a smaller "nice to have" list).

## Day 2 & 3: Build the Core

Minimum build recipe:

1. **Input** — simplest possible: a text box, a file upload, a sheet.
2. **AI brain** — a well-prompted model (your SCoPE skills) or a simple agent.
3. **Output** — one clear deliverable: a summary, a file, a chart, an answer.
4. **Polish** — one quality touch (clean copy, a logo-free interface, error message on bad input).

**No over-engineering.** A working 80% shipped Monday beats a perfect 95% shipped never.

Use the Mission 6 loop: EXPLAIN/WRITE/DEBUG with AI, Copy → Run → Understand, test on copies.

## Day 4: Real-User Test (Even One Friend Counts)

Ship the ugliest working version to **1–3 real users** (classmates, society members, a friend in the domain):

- Watch them try it silently for 3 minutes. Note where they pause.
- Ask 3 questions: *What did you use it for? What broke or confused you? What would you actually pay/use this for daily?*
- **You will discover the thing you didn't expect.** That's the point of testing.

Then make **2 quick fix rounds**. Prioritise the crash/confusion bugs; note the rest as "v2 ideas."

## Day 5: Package & Share

Make it presentable:

- **README:** What it does → How to run it → Screenshots → What I learned.
- **Screenshots/Loom:** 60-second demo recording (voice optional, always caption).
- **Deploy or demo-ready:** a free hosting option (Streamlit/Netlify/GitHub Pages) or a clean demo video if sharing code isn't possible.
- **Honest AI line:** "Built with AI assistance for Code; design and logic decisions were mine." — this is exactly what employers want to hear.

## The Reflection Loop (What Makes It Portfolio-Worthy)

After shipping, write 5 short answers:

1. What problem did I pick and why?
2. What did the user test teach me?
3. What was the hardest technical moment, and how did I solve it?
4. What would I do differently in v2?
5. Which skill from Missions 1–7 did I actually use most?

Real, honest, specific reflections beat "perfect projects" every time in interviews.

## Mini-Project Ideas Quick List

- Notes → flashcards generator
- Canteen/bus/timetable chatbot for your campus
- Syllabus → weekly study plan tool
- Old past papers → practice quiz generator
- Any paper → one-page "exam-friendly" summary
- Your research area → terminology glossary generator

## Key Takeaways

- One week, one user, one problem: scope to a sentence.
- MVP: input → AI brain → output → one polish pass.
- Test with real users early; you'll learn what's actually broken.
- Package it: README + demo + honest AI-use note.
- Write the reflection — that's what turns a toy into a portfolio piece.

## Practice Challenge (This IS the mission)

1. **Day 1:** Write your one-paragraph project brief and the "My project helps ___ do ___" sentence. Get it approved by a classmate or mentor.
2. **Day 2–3:** Build the working MVP (input → AI → output). Run it on at least 3 test inputs.
3. **Day 4:** Get 1+ real user to try it. Collect their 3 feedback answers, fix the top 2 issues.
4. **Day 5:** Publish the README + 60-sec demo + honest AI line somewhere shareable (GitHub, a doc, or a video link). Submit the shareable link + your 5 reflections as the mission assignment.
