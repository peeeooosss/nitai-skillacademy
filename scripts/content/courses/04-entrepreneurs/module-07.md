### Module 2 · Step 1: Map the Flow (Pipeline Thinking)

Before automating, map the flow: what triggers it, what steps happen, and what the output is. Pipeline thinking turns messy work into a clear diagram.

A flow is: **trigger, steps, output.** If you cannot draw it, you cannot automate it reliably.

## Learning Objectives

- Map a flow as trigger, steps, output
- Identify the inputs and outputs
- Find the repetitive core
- Prepare the flow for automation

## Trigger, Steps, Output

- **Trigger:** what starts the flow (form, email, date, new customer)
- **Steps:** the actions between trigger and output
- **Output:** the result (record, reply, invoice, post)
### Why
- Clear flows are automatable
- Ambiguity breaks automations
- Mapping reveals waste

## Inputs and Outputs

- Name every input the flow needs
- Name the exact output it must produce
- Note decisions and exceptions
### The rule
- One flow, one purpose
- Exceptions are where automations fail
- Handle the common path first

## The Mapping Prompt

```text
Map this repeated task as a flow: [describe task].
Give me trigger, steps, output, inputs, and exceptions.
Then suggest which steps a no-code tool or AI can do
and which must stay human.
```
- Trigger, steps, output, inputs, exceptions
- Flag what AI can do
- Keep human steps visible

## Key Takeaways

- Map flows as trigger, steps, and output
- Name every input and the exact output
- Clear flows are automatable; ambiguity breaks them
- Handle the common path first, then exceptions
- Flag which steps AI can do and which stay human

## Practice Challenge

1. Draw one repeated task as trigger, steps, output
2. List its inputs, exceptions, and human steps
3. Identify the repetitive core to automate

### Module 3 · Step 2: Your Automation Won't Have Boxes — It Has Magic Glue

Old-school automation was boxes and arrows in enterprise software. Yours is **magic glue**: small no-code connectors that link the tools you already use.

The magic glue approach is simpler and cheaper: connect a form to a sheet, a sheet to an email, an email to a reminder. That is often the whole automation.

## Learning Objectives

- Understand the magic-glue approach
- Connect existing tools with no-code connectors
- Build simple chains of apps
- Avoid over-engineering

## Magic Glue, Not Boxes

- Enterprise automation means boxes and arrows
- Yours means small connectors between tools
- The glue is invisible to the customer
### Why
- You already use the tools
- Connectors are cheap and fast
- No enterprise software required

## Connecting Existing Tools

- Form to sheet: capture and store
- Sheet to email: notify and follow up
- Email to reminder: never forget
### The rule
- Use what you already have
- Add one connector at a time
- Keep the chain short

## The Glue Prompt

```text
Using my existing tools [list tools], design the simplest
no-code automation chain for [task]. Show the connectors
between them, what triggers each step, and the exact output.
Prefer fewer tools and a short chain.
```
- Fewer tools, shorter chains
- Show triggers and outputs
- Keep it maintainable

## Key Takeaways

- Modern automation is magic glue, not enterprise boxes
- Connect tools you already use with no-code connectors
- Chains: form to sheet, sheet to email, email to reminder
- Add one connector at a time and keep chains short
- Prefer fewer tools and maintainable flows

## Practice Challenge

1. List the tools you already use
2. Design one short automation chain
3. Connect the first two tools

### Module 4 · Step 3: Build Three Working Automations

Three automations are enough to feel the leverage: one for **capture** (leads or orders), one for **follow-up** (replies or reminders), and one for **records** (logging or reporting).

Build them one at a time, test each, and keep them simple. Three working automations beat ten half-built ones.

## Learning Objectives

- Build one capture automation
- Build one follow-up automation
- Build one records automation
- Test and keep each reliable

## The Three Automations

- **Capture:** new lead or order lands in one place automatically
- **Follow-up:** a reply or reminder goes out on schedule
- **Records:** data logs itself for reporting and taxes
### Why these three
- They cover the core solo-founder workload
- Each is simple to build
- Together they save real hours

## Building One at a Time

- Build capture first - it feeds the rest
- Add follow-up next - it drives revenue
- Add records last - it keeps you sane
### The rule
- Test after each build
- Keep each one simple
- Three working beats ten half-built

## The Build Prompt

```text
Give me step-by-step no-code build instructions for three
automations for [business]: (1) capture leads/orders,
(2) follow-up replies/reminders, (3) log records for reporting.
Use [tools]. Include how to test each one.
```
- Step-by-step keeps it doable
- Testing instructions prevent silent failure
- One build per session

## Key Takeaways

- Build three automations: capture, follow-up, records
- Capture feeds the rest; follow-up drives revenue; records keep order
- Build and test one at a time
- Keep each automation simple
- Three working automations beat ten half-built ones

### Module 5 · Step 4: The Traps (And How to Not Fall In)

Automation has predictable traps: over-engineering, brittle chains, and automating a broken process. Each one wastes time and erodes trust in the system.

The fixes are simple: start minimal, test often, and fix the process before you automate it.

## Learning Objectives

- Recognise the common automation traps
- Avoid over-engineering and brittle chains
- Fix processes before automating them
- Keep automations trustworthy

## The Three Traps

- **Over-engineering:** building a complex chain for a simple task
- **Brittle chains:** one broken link stops everything
- **Automating a broken process:** you just get faster chaos
### Why they hurt
- Complexity is hard to maintain
- Brittle flows fail silently
- Automating waste multiplies it

## The Fixes

- Start minimal and add only what you need
- Test often and monitor outputs
- Fix the process before automating it
### The rule
- Simple and reliable beats clever
- Watch the first weeks closely
- Remove automations that do not earn their keep

## The Trap-Check Prompt

```text
Review this automation plan [describe] for the three traps:
over-engineering, brittle chains, and automating a broken process.
Suggest simplifications and the tests I should run.
```
- Review before you build
- Simplify where possible
- Plan the tests

## Key Takeaways

- Common traps: over-engineering, brittle chains, automating broken processes
- Complex chains are hard to maintain; brittle flows fail silently
- Automating waste just multiplies it
- Start minimal, test often, fix the process first
- Simple and reliable beats clever

## Practice Challenge

1. Review your automation plans for the three traps
2. Simplify one chain
3. List the tests you will run

3. What happens if you automate a broken process?

**Answer:** A — Fix the process first, or automation multiplies the waste.

4. What beats clever?
- A) Simple and reliable
- B) Complex

- D) Fast

**Answer:** A — Simple, reliable automations earn their keep; remove the rest.

### Module 6 · Step 5: Measure the Win in Hours

The value of automation is measured in hours saved, not in how clever the flow is. Track the time each automation returns and keep only the winners.

If an automation saves ten minutes a day, that is over 40 hours a year. Multiply across three automations and the leverage is real.

## Learning Objectives

- Measure hours saved per automation
- Compare value to maintenance cost
- Keep the winners, remove the losers
- See automation as compounding leverage

## Hours Saved

- Time each automation saves per week
- Multiply to see the yearly return
- Ten minutes a day is 40+ hours a year
### Why hours
- Hours are the scarce resource
- Hours compound into progress
- It is the honest measure of value

## Value vs Maintenance

- Subtract the time spent maintaining the flow
- Keep automations that save more than they cost
- Remove or simplify the rest
### The rule
- Measure, do not assume
- Review monthly
- Cut the losers

## The Measurement Prompt

```text
Help me measure my automations: for each, estimate minutes
saved per week, yearly hours, and maintenance time. Then rank
them and flag any that are not worth keeping.
```
- Estimate weekly savings
- Rank by yearly return
- Flag the ones to cut

## Key Takeaways

- Measure automation value in hours saved
- Ten minutes a day is 40+ hours a year
- Subtract maintenance time from the savings
- Keep winners, remove or simplify losers
- Review monthly - automation is compounding leverage

## Practice Challenge
